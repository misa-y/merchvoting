# Independent public rehearsal preview

This preview is a static build of `utokyo-design-lab`. It is hosted as its own Sites project (`appgprj_6afeb1e44648819182584796f19bfe40`), separate from the original GitHub Pages site. No Pages settings, custom domains, DNS records, or `main` files are changed.

- Voting: https://mustang-market-utokyo-design-lab.bladedcornbread5.chatgpt.site/
- Analytics: https://mustang-market-utokyo-design-lab.bladedcornbread5.chatgpt.site/admin.html

Open the links directly in Safari on the iPad. No local server or laptop connection is needed. Landscape is best for presenting voting and analytics side by side; portrait layouts are also supported. The analytics dashboard scrolls vertically when necessary.

## Demonstration data

The public build enables `MERCH_PUBLIC_DEMO` in `preview-config.js`. The ordinary local checkout keeps the flag off, preserving the prototype's existing records and import functionality.

Public mode:

- Starts with **30 fictional participants × 12 products = 360 synthetic votes**.
- Clearly labels all pages and analytics as simulated/rehearsal data.
- Uses its own `mustang-market-public-demo-v1` browser database.
- Disables original-record importing in both the UI and storage API.
- Saves interactions as `demonstration-interaction`, separate from the seeded synthetic records' `demonstration` source.
- Updates local analytics after voting; **Demo data tools → Restore sample data** restores the original 360-vote scenario.
- Never sends votes to a server or shares them across devices. Your iPad and laptop have independent rehearsal state.

There are no student records or browser exports in the deployment. The seed is generated by code in `store.js`. This is a demonstration, not a student survey or a method of verifying 30 real participants.

## Rebuild safely

Only build from `utokyo-design-lab`, after committing the intended source:

```sh
node scripts/build-public-preview.cjs /absolute/path/to/new-empty-dist-directory
```

The builder refuses another branch or a nonempty destination, copies an explicit list of app files and original PNGs, enables public-demo mode only in its output, and writes `preview-provenance.json` with the source commit. It never copies `.git`, dependency folders, test files, browser data, or credentials.

The independent hosting checkout is `work/utokyo-public-preview` in the parent task workspace. Its `.openai/hosting.json` owns the Sites identity; do not move that manifest into the production repository or alter the original GitHub Pages configuration. Use the Sites workflow to package and publish its `dist` directory. Rebuilding the GitHub branch alone does not automatically republish the separate hosted snapshot.
